# Agents

Rules for AI coding agents working in this repository.

## General

- Follow existing code conventions and patterns
- Do not modify files outside the scope of the current task
- Prefer editing existing files over creating new ones
- Do not add dependencies without explicit approval
- Keep changes atomic -- one concern per commit
- Ask for clarification when requirements are ambiguous
- Do not generate PR descriptions or review comments on others' code
- Use type hints for function and method parameters, return values, and variables where their types are not clear. Follow Python's standard typing conventions (PEP 484 and related typing PEPs), using the syntax supported by the project's Python versions.
- Declare type hints for instance attributes initialized in `__init__` in the class namespace, rather than inside `__init__`

## Testing

Write tests for new functionality.

Read [tests/README.md](tests/README.md) for test organization, fixtures, platform/backend restrictions, and test commands. For Pyodide browser testing, also read [tests/pyodide/README.md](tests/pyodide/README.md). These documents explain how to write and run tests; they do not authorize a test run. Follow the execution rules below.

- Run the full suite before preparing a pull request for submission.
- Do not run the full suite for routine work unless explicitly requested.
- During local development, run focused tests for the changed behavior and directly affected integrations. Do not test unrelated subsystems.

## Commits

- Use clear, descriptive commit messages
- One logical change per commit
- Reference relevant issues when applicable

## Review

Changes touching more than one module or any security-relevant code require human review. Minor fixes and doc updates follow the standard process.
